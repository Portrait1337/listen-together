# 消息撤回功能设计

## 需求

- 用户长按自己发出的聊天消息，弹出「撤回」按钮，点击后撤回该消息；
- 他人消息不显示撤回入口；
- 撤回后：在线成员同步移除该消息，新成员进房看不到该消息。

## 方案

### 服务端（server.js）

- 每条聊天消息新增唯一 `id`（`crypto.randomBytes`）。
- 新增 WebSocket 消息类型 `recall_message`，携带 `id`：
  - 消息不存在 → 忽略；
  - 发送者昵称与该消息昵称不一致 → 忽略（当前无账号体系，按昵称判定本人）；
  - 成功 → 从 `room.chatHistory` 移除该消息，广播 `message_recalled { id }`。
- 历史消息（`chat_history`）不再包含已撤回的消息。

### 前端（public/app.js）

- `appendChat(nick, text, id)` 记录消息 `id` 与「是否自己发送」（昵称一致）。
- 自己消息支持长按（touch 500ms）与右键（contextmenu）弹出「撤回」按钮；
- 点击「撤回」发送 `recall_message`；
- 收到 `message_recalled` 后按 `id` 从聊天列表移除对应消息。

### 测试

- 服务端：本人可撤回；他人不可撤回；撤回后历史不再包含；无效 id 忽略。
- 前端（DOM 桩）：长按自己的消息出现撤回按钮并发送撤回；长按他人消息不弹。

## 边界与限制

- 没有登录体系，同昵称的用户可撤回该昵称的消息；如需严格权限需引入用户 ID。
- 撤回采用直接删除，不显示「已撤回」占位。
